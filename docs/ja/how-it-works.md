# HiCarta のしくみ

HiCarta が大きな Hi-C データを軽快に表示できる理由と、データの読み込み方を説明します。基本操作については **[使い方](usage.md)** を参照してください。

## R とブラウザの役割

HiCarta は、R の Shiny で作られたアプリです。起動すると、お使いの PC 上で R がローカル Web サーバー（`http://127.0.0.1:7788`）として動き、Web ブラウザがその画面を表示します。

- **R** — ファイルの読み込み、行列の取り出し、色の割り当て、トラックの描画、PDF の出力を行います。
- **Web ブラウザ** — 画面の表示と、ドラッグやスクロールなどの操作を処理します（地図の表示には Leaflet を使っています）。

どちらも同じ PC の上で動くため、専用のサーバーを別に用意する必要はありません。読み込んだデータが外部の計算用サーバーに送られることもありません。

## タイルで描画する

Web 地図アプリと同じように、HiCarta はマップを **256 ピクセル四方のタイル**に分けて描画します。

1. 画面に表示されている範囲のタイルだけを要求します。画面の中央に近いタイルから順に描画されます。
2. タイルごとに、そのタイルに対応する 2 次元の領域だけを `.hic` ファイルから読み込みます。読み込む解像度は、拡大率に応じて自動的に選ばれます（Level of Detail（LOD））。
3. 読み込んだ値に色を付け、画像としてブラウザに送ります。表示領域から離れたタイルは破棄されます。

色は、すべてのタイルで共通のカラースケールを使うため、タイル間で色のスケールが統一されます。マップを開いたときに、全体を低解像度で走査して最大値の初期値を決めます。

## リモートのファイルを部分的に読む

HiCarta は、`.hic` と bigWig を読むための R で実装した独自のリーダーを備えています。ファイルの中の索引をたどり、必要なバイト範囲だけを HTTP レンジリクエストで取得します。

- Web サーバー、Dropbox の共有リンク、Amazon S3 に置いたファイルも、**全体をダウンロードせずに**表示できます。
- 確立した接続を再利用し、読み込んだデータはメモリにキャッシュします。一度見た領域に戻るときは、キャッシュを利用して高速に表示できます。
- 通信が遅い環境や不安定な環境では、`config.txt` で `hic_engine = download` にすると、ファイル全体を先に `_hic_cache/` フォルダに保存してから読み込みます。最初の表示までは時間がかかりますが、その後の操作が安定する場合があります。
- BED、GFF3、Border Strength のファイルは、最初にファイル全体を読み込みます。GFF3 は解析結果を `*.genes.rds` として保存するので、2 回目からは速く開けます。

## 非公開のファイルを読む

カタログに `s3://バケット名/キー` の形で書いたファイルや、公開されていない S3 のファイルは、PC に保存した AWS のアクセスキー（`~/.aws/credentials`）でリクエストに署名して読み込みます。読み込みの可否は S3 側のアクセス権限で決まります。ファイルに付けたタグと、ユーザーごとの権限の組み合わせで、研究室やグループの単位で共有範囲を分けられます。→ [非公開の S3 データを読む](data-catalog.md#private-data-on-amazon-s3)

## 座標

マップの原点は左上で、ゲノムの座標は右（X 軸）と下（Y 軸）に向かって増えます。トラックは X 軸の座標に合わせて描かれます。
