# データカタログ（.xlsx）

HiCarta では、コンタクトマップやトラックを **データカタログ** から開くことができます。カタログは Excel ファイル（`.xlsx`）で、**1 行につき 1 サンプル**の情報を記載します。カタログを使わずにファイルのパスや URL を直接指定することもできます。画面上部の **データ** ボタンから **データブラウザ** を開き、カタログを読み込むと、絞り込みや検索が可能なサンプル一覧が表示されます。行をクリックすると、そのサンプルの詳細情報が表示され、ファイル形式に応じた操作（コンタクトマップとして開く／比較として開く／トラックとして追加／IGV で開く）が選べます。

すぐに利用できるテンプレートをリポジトリに用意しています。
[`HiCarta_catalog_template.xlsx`](https://github.com/rafysta/HiCarta/blob/main/HiCarta_catalog_template.xlsx)

カタログはローカル環境やネットワークドライブに保存するほか、HTTP で公開・共有した `.xlsx` の URL を指定することもできます。カタログは読み込み操作のたびに再取得されるため、共同研究者が共有ファイルを編集した場合も、次回の読み込み時に変更を反映できます。Google スプレッドシートには対応していません（`.xlsx` として書き出して共有してください）。

---

## カラム

### 必須

| カラム | 意味 |
|---|---|
| `id` | 数値。一覧表示と ID 検索に使います。**値は一意であることを推奨しますが、重複も許容されます。** 重複した行は除外されず、警告が表示されます（HiCarta 内部では ID をキーとした行の参照を行いません）。番号体系の異なるサンプル群を 1 つのカタログにまとめられるようになっています。 |
| `name` | 一覧に表示するサンプル名。 |
| `path` | ファイルのパスまたは URL。`;` 区切りで**複数のエントリ**を持てます（後述）。 |

### 推奨（HiCarta が認識するカラム）

| カラム | 意味 |
|---|---|
| `file_type` | `hic` / `bigwig` / `bed` / `gff3` / `bs`。空欄なら拡張子から推定。 |
| `experiment_type` | HiC、ChIP-seq、RNA-seq など。絞り込みに利用できます。 |
| `project` | プロジェクト名。絞り込みに利用できます。 |
| `sample_sheet` | サンプルシート／バッチの識別子。絞り込みに利用できます。 |
| `date` | `YYYY-MM-DD` 推奨。`YYYY/MM/DD`・`YYYY.MM.DD`・`YYYYMMDD`・Excel の日付セルも可。期間で絞り込めます。 |
| `genome` | ゲノム／アセンブリ名。 |
| `label` | `path` の `;` エントリごとの表示ラベル（`path` と同数、または 1 つで共通）。 |
| `comment` | 自由記述。全カラム検索の対象になります。 |

### 設定カラム（`set_` プレフィックス）

名前が `set_` で始まるカラムには、**そのサンプルを開くときに適用する既定値**を指定します。一覧やフィルタには現れません。

| カラム | 開くときの効果 |
|---|---|
| `set_norm` | 選択する正規化（`ICE`・`KR`・`NONE` など）。未指定なら **ICE → KR → Raw** の優先順でファイルが持つものを自動選択。 |
| `set_vmax` | カラースケール最大値の初期値。 |
| `set_resolution` | 表示解像度（bp）を固定し、ズームに連動した自動切り替えを無効にします。 |
| `set_color` | トラックの既定色（トラック形式のとき）。 |
| `set_height` | トラックの既定の高さ（px）（トラック形式のとき）。 |

### 自由カラム

それ以外のカラムも保持され、詳細画面に表示されます。**異なる値が 20 個以下**のカラムは自動的にサイドバーのドロップダウンフィルタになるので、`tissue` や `condition` のようなカラムを追加するだけで絞り込みに使えます。

## 1 行に複数ファイル（`;`）

`path`・`label`・各 `set_` カラムは `;`（全角 `；` も可）区切りで複数の値を持てます。同じ行では、これらのカラムは **1 個**（全エントリ共通）か **`path` と同数**のどちらかです。

主に次の 2 つの用途があります。

- **トラックのセット** — 1 サンプルに属する複数の bigWig など。「トラックとして追加」でエントリを選べます。
- **仮想マルチ解像度データセット** — 同じサンプルの単一解像度 `.hic` を 1 行にまとめる。行を**「自動」**で開くと 1 つのデータセットとして扱い、ズームに応じてファイルを切り替え、明るさも調整します。これは既存の解像度別ファイルのための互換機能で、新しいデータには、1 つのマルチ解像度 `.hic` を使用することを推奨します。

!!! note
    「自動」では**全ファイルに共通する正規化**だけが「表示 → マップ → 正規化」に並びます。特定ファイルの正規化を使うには、そのエントリを単独で開いてください。

## ディレクティブ行：`#show`

`id` セルが `#show` の行はデータではありません。**最初から一覧に表示したいカラム**に任意の値（例：`1`）を入力してください。表示カラムは **Columns** ボタンでいつでも変えられます。`id` と `name` は常に表示されます。`#` で始まるが未知のディレクティブの行は警告とともに無視されます。

---

## バリデーション

カタログの読み込み時に、`id` の欠落や数値以外の値、空欄の `path`、`;` で区切った値の個数の不一致などがある行は **除外** されます。軽微な問題（`id` の重複、**ファイル名にも URL にも見えない `path`**、解釈できない日付、未知の `file_type` や `set_` カラム）は警告のみで、行は読み込まれます。

`path` の形については、URL スキーム（`https://` など）・パス区切り（`/` や `\`）・拡張子のいずれかがあれば正常とみなします。いずれも含まない値（`ICE`、`KR`、`5000` など）は**カラムがずれている典型的な兆候**なので警告します。該当するファイルを開こうとした場合も、処理が中断され、その理由が表示されます。

表の上には**件数だけ**が「除外された行: 3 件（クリックで詳細）」のように 1 行で表示されます。その行をクリックすると、サンプル名と理由付きの一覧が開きます（同じ行をもう一度クリックすると閉じます）。件数が多い場合、一覧は先頭 200 件までで、残りは「ほか N 件（省略）」とまとめられます。

## ブックマークの Excel 入出力 {#bookmarks-as-excel}

ブックマーク（**移動**パネル）が記録するのは**場所だけ**（染色体と X／Y の範囲）です。クリックすると現在開いているデータのその領域へ移動するので、注目領域をサンプル間で見比べる用途にそのまま使えます。`.xlsx` との入出力は 次の 2 つのボタンで行います。

- **Excel に保存** — 現在のリストをダウンロード（1 行 = 1 ブックマーク。カラムは `bookmark_name, chr, start, end, chr_y, ystart, yend, comment`）。
- **Excel から読み込み（追加）** — ファイルの行を現在のリストに**追加**します。既存のブックマークは変更されません。不正な行はカタログと同様に除外され、名前と理由が表示されます。旧版が書き出した `catalog_id` / `path` / `norm` などのカラムを含むファイルもそのまま読めます（これらのカラムは無視されます）。

通常の Excel ファイルなので、`comment` 列に注釈を書く、注目領域のリストを手で作る、共同研究者と共有する、といった使い方ができます。

## 非公開の S3 データを読む {#private-data-on-amazon-s3}

`path` には、公開 URL のほかに **`s3://バケット名/キー`** の形で Amazon S3 上のファイルを書けます（例：`s3://uo-cgf/P/020/NAME/NAME.hic`）。`.hic`・bigWig・BED などすべての種類で使え、カタログ自体を S3 に置くこともできます。

- **公開されているファイル**は、これまでどおり認証なしで読みます。`https://….amazonaws.com/…` の URL でも `s3://` でも構いません。
- **公開されていないファイル**は、PC に保存した AWS のアクセスキーを使ってリクエストに署名し、読み込みます。読めるかどうかは S3 側の権限（ラボ・P01 などのグループ）で決まり、権限がない場合は「権限がない」旨のメッセージが出ます。
- `https://` の S3 URL で書いたファイルが後から非公開になっても、必要なアクセス権限があれば同じ URL のまま読めます。

アクセスキーの置き場所（AWS CLI と同じファイル）:

```ini
# Windows: %USERPROFILE%\.aws\credentials   Mac: ~/.aws/credentials
[hicarta]
aws_access_key_id     = AKIA...
aws_secret_access_key = ...
```

**設定 → 設定ファイルを編集…** の「AWS プロファイル」に `hicarta` と入力して保存します（空欄なら `[default]`）。設定画面には、アクセスキーが見つかったかどうかが表示されます。アクセスキーは `config.txt` には保存されません。リージョンは自動で判定されます。

## IGV で開く {#open-in-igv}

トラック行の詳細表示には **IGV で開く**ボタンがあります。ファイル（と現在表示中の領域）を、**起動済みの IGV デスクトップ**に IGV のリモートポート経由で送ります。HiCarta は IGV を自動起動しません。あらかじめ IGV を起動し、初回のみリモートポートを有効にしてください。*View → Preferences → Advanced → 「Enable port」*（既定 60151）。`config.txt`（または **設定 → 設定ファイルを編集…**）の `igv_genome` を設定すると、読み込むゲノムも IGV に伝えます。

## 旧形式との変換

`scripts/` に、カタログと 2 つの旧形式（Juicer 形式メニュー、IGV トラックリスト XML）を相互変換する4 つの変換スクリプトを用意しています。

```bash
Rscript scripts/juicer_menu_to_catalog.R  menu.txt     catalog.xlsx [--collapse]
Rscript scripts/igv_xml_to_catalog.R      tracks.xml   catalog.xlsx
Rscript scripts/catalog_to_juicer_menu.R  catalog.xlsx menu.txt
Rscript scripts/catalog_to_igv_xml.R      catalog.xlsx tracks.xml
```

`--collapse` を付けると、正規化別の旧ファイル名（`NAME_ICE.5kb.hic` → `NAME.hic`）を書き換えて重複を除きます。データを単一のマルチ解像度 `.hic` として再生成した後に便利です。詳しくは
[scripts/README.md](https://github.com/rafysta/HiCarta/blob/main/scripts/README.md) を参照してください。
